# Asset system flowchart

The flowchart shows every file an asset holds, the commands and tools that load and save each one, the scene nodes they become, and where poses, animation and clips go when they leave the rig. It is a page published with the Artifact tool and generated by `generate.py` beside this file (plain Python 3, no dependencies).

- **Artifact:** https://claude.ai/artifact/McfZB5Fc8GWstsVaeypKsd (private to the author). Update it in place: from a new conversation, `read` it first, then publish with `url` set to it. Never publish a second copy.
- **Last drawn from:** RigModules `9dc46fc` plus the doc fixes on branch `ccr-c928f9a7-a9ta7a`, and mayadev `6ae0473` plus the same. The page prints the two SHAs passed to `generate.py`. Pass the commits you read.

## Procedure

The slow part the first time was reading about 8,000 lines of docs across two repos. Read only what changed.

1. **Read `main`, not the local branch.** Clones in a session can be far behind (on 2026-11-24 the RigModules clone was 40 decisions behind). Run `git fetch origin main` in both repos, then read with `git show origin/main:<path>`, or for many files, `git worktree add <scratchpad>/rm-main origin/main` (remove the worktree afterwards). mayadev is `benmorgantd/mayadev`; attach it with `add_repo` if it isn't cloned.
2. **Diff the sources since the last drawing.** Use the SHAs above: `git diff <sha> origin/main -- <the source pages below>` in each repo. If nothing in the table changed, the diagram is current: say so and stop. Otherwise read only the changed hunks, plus `design/decisions.md`'s Index rows for any new decision ids they mention.
3. **Edit `generate.py`**, one block per diagram region (its docstring lists them in order). Copy it to the scratchpad and run it there:
   `python3 generate.py --out <scratchpad>/asset-flow.html --rigmodules-sha <sha> --mayadev-sha <sha>`
4. **Look once.** Take one screenshot of the SVG and fix what it shows in one pass. Then publish. `require('playwright')` works in the cloud container:
   ```js
   const { chromium } = require('playwright');
   (async () => { const b = await chromium.launch(); const p = await b.newPage({ viewport: { width: 1600, height: 1300 } });
     await p.goto('file://' + process.argv[2]); await p.waitForTimeout(800);
     await (await p.$('.scroller svg')).screenshot({ path: process.argv[3] }); await b.close(); })();
   ```
5. **Doc conflicts.** When two pages disagree, or a page disagrees with the code, check the code on `main` (the code wins). Add the conflict to `DOC_CONFLICTS` so the page lists it, and tell the author. Fixing the docs needs the author's go-ahead, mayadev's included. Once they are fixed, empty the list.
6. If the change is lasting, update `generate.py` here and the SHAs above in the same commit.

## Sources and what each feeds

| Source on `main` | Feeds |
|---|---|
| mayadev `docs/assets.md` | The main source. File types and paths (`project.json` `fileTypes`), `asset.json`, `rig.json`, `look.json`, the handlers table (load and save per file type), the Registry, publishes and their gates, local versions, source control, `build_rig` steps (the ①–⑥ order), `apply_look`, `textures.json`, the library sources |
| mayadev `docs/clips.md` | The exports bundle, `sources/`, the skeleton export, `animproperties.json`, capture and load of clips |
| mayadev `docs/tools.md` | Menu tool names (Save Model, Capture Joint Clip, ...) and the Asset Editor |
| RigModules `docs/library.md` | Control data and skeleton data, ControlAnim and ControlPose formats and versions, the library folders |
| RigModules `docs/skinning.md`, `docs/skeletons.md`, `docs/looks.md` | Weight file, skeleton file and `setRigLook`: what each matches on (`meshId`, markup, `skeletonHash`) and format versions |
| RigModules `docs/python.md` (`rigmodules.jointclip`, bone maps) | JointClip and bone map formats, `read_fbx`, `write_fbx`, `write_skeleton_fbx` |
| RigModules `docs/commands.md` | Command names and the rig root stamps (`createRigFromTemplate`) |
| RigModules `design/asset-model.md` | Why: the repo split, the Perforce rule, the id rules |

Not drawn: `design/asset-pipeline.md` (the art stages before the rig), which is a proposal. Draw it only when it is built.

## Layout rules (so edits don't break the drawing)

- Canvas 1520 by 1062. Lanes (x, width): asset folder 40/230, load and save 330/240, Maya scene 630/230, capture and apply 920/240, library, clips and engine 1220/270.
- The main band and the bottom band sit inside `translate(0,22)`, so the first row clears the lane headers. Rows are 85 apart (centres 250 to 760 before the shift), and a row box is 64 high.
- Text widths: mono at 10.5 px is about 6.3 px a character, so about 34 characters in a 240 box. Sans at 11 px is about 5.8 px. Overflow was the main fix after the first screenshot: shorten the text, don't widen the box.
- Edges between columns run straight where the rows line up. Elbows use their own x channel (890 between scene and capture, the right margin at 1508 for exports to the engine), so vertical segments never overlap.
- Colour is the format's owner: RigModules (blue), mayadev (ochre), Maya ASCII (violet), FBX (green). Tools are white with solid borders, and scene nodes are dashed. Keep the four colours meaning owners: the legend says so.
- Numbered badges mean the `build_rig` order only. Don't number anything else.
