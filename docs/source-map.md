# Source map

The per-file reference for the whole repo: what every file under `cpp/core/` and `cpp/maya/` holds, the Python package, the `design/` pages, and the tools. It is the long form of the source map in [`architecture.md`](architecture.md), which gives the shape of the code and how a rig is built. Search here before searching the repo. Paths in the C++ tables are relative to `cpp/`.

When a file is added, renamed or changes what it holds, update its row here in the same change (the docs pass in `CLAUDE.md`).

| `AssetId.h/.cpp` | `AssetId::isValid` and `AssetId::name` (the last token, the default rig namespace) for `\`-separated asset ids (D29), and `isValidName`, the lowercase folder-name rule for id tokens and rig, skeleton and look names (D54). |
| `JsonUtils.h` | Header-only `readJsonString` / `writeJsonString`. Every string attribute that holds structured data (socket names, joint markup) goes through these (D16). |
| `StringUtils.h` | Header-only string helpers: `splitIdentifier` for `"module.name"`, `joinNames` (`"a, b, c"` for messages), `endsWith`, `trim` (a namespace's colons), `toSnakeCase` (the default `rigName`), `stripNumberSuffix` and `numberedName` (`spine_00` and `spine`, `spineIK` and `spineIK_02`: derived control names, D57). Included by `maya/shared/Utilities.h`. |
| `RigJsonStructs.h/.cpp` | Template structs (`RigRootData`, `RigModuleData`, constraint data), `templateUpdateTable` and `loadRigTemplate` (update steps, key checks, then parse). |
| `FormatUpdate.h/.cpp` | `UpdateTable` and `FormatUpdate::runUpdates`: a saved format's version steps, run in order on raw JSON (D33). Used for the template and, through `ModuleDescriptor::argUpdates`, each module's `moduleArgs`. |
| `ControlChannels.h/.cpp` | `ControlChannel` (name, type, rest, range, mirror mode), `serializeControlChannels` for `getRigControlChannels`, `ControlSpace` (constraint or module, labels, current) with `serializeControlSpace` for `getRigControlSpace` (D50, D52), and `findMirrorAxis` for flipping a Center control (D34). |
| `RigTemplateValidation.h/.cpp` | `ValidationReport`, `ModuleInterface` (its `ModulePlugInfo`: `hasControl`, `allowsConstraint`, and `followsPlug` for an internal child plug, D52), and the read-phase template checks (D17), and the `parent:` id helpers `isParentSocketId`, `stripParentPrefix`, `isDrivenByParent` and `parentSocketIds` (D55). |
| `TemplateMirror.h/.cpp` | `expandMirrors` (adds the other side's copy of every `"mirror": true` module and constraint before validation), `swapSide`, `swapSideSuffix` (D28). |
| `SelectionSets.h/.cpp` | `SelectionSets::planSets`: the selection set hierarchy a rig gets for one kind (controls or skin joints: top set, sides, modules) from `{module, side}` items, as names, `setMarkup` JSON and member indices (D39). |
| `JointMarkup.h/.cpp` | Markup schema, `JointSelector` (and `formatJointSelector` for messages), `JointMarkupIndex`. |
| `ControlMarkup.h/.cpp` | Control markup schema (`controlMarkup` attribute): `markupVersion`, `side`, `usage` (D25), and `ControlInfo` with `serializeControlInfo` for `getRigControlInfo` (D34). |
| `ControlShapes.h/.cpp` | `ShapeType` enum, shape name lookups, `getShapeMesh` (wire and triangle indices, built once by ear clipping) and `validateShapeLibrary` (D26). |
| `ControlShapeLibrary.h/.cpp` | The shape mesh data. The .cpp is generated by `tools/generate_control_shapes.py`: never edit it by hand. |
| `ControlShapeFile.h/.cpp` | Shape file format (version 2, with `wireframeAlpha`): `ControlShape`, `ControlShapeMap`, `controlShapeUpdateTable` (D33), `serializeControlShapes` / `deserializeControlShapes` (D26). |
| `RibbonMath.h/.cpp` | The Ribbon module's solve with no Maya types (D56): `Vec3`, `Mat4` (row vectors, rows are the axes), `Params` (the 15 channels in internal units, defaults are the rest), `Setup` (what the rest pose fixes: knots, bind parameters, rest length and frame, the interior controls' and bind joints' rest offsets), `buildSetup`, `evaluate` (a Hermite spline through the controls, frames by parallel transport on a fixed table, twist, a sine layer, scale and volume), `extractTwist`, `wrapAngle` and `pickTwistBranch`. A pure function: no state, no allocation. |
| `VectorMath.h` | Header-only `Vec3`, `Mat4` (row vectors, rows are the axes) and the small vector helpers (`add`, `sub`, `scale`, `dot`, `cross`, `length`, `normalized`, `lerp`, `row`, `origin`, `makeFrame`, `anyPerpendicular`, `rotateByArc`) that `RibbonMath` and `ControlPlacement` share. `RibbonMath::Vec3` and `Mat4` are aliases of these. |
| `ControlPlacement.h/.cpp` | Where a module's controls go with no control joint (D57, design/derived-controls.md): `checkChain` (every bind joint's X axis within 60 degrees of the chain and all the same way, returning the chain sign, +1 or -1) with `describeChainProblem`, `placeAlongChain` (frames evenly by arc length along a smooth spline through the joints, rotation slerped between the bracketing joints), and `placeLimb` (a two-bone limb's pole and settings positions, with optional world-space offsets). Pure functions run in the read phase. The Ribbon uses `checkChain` and `placeAlongChain` (D57 phase 2). `placeLimb` is not used by a module yet (phase 3). |
| `SwingTwist.h/.cpp` | The swing-twist split about X with no Maya types (design/ribbon-twist-follow.md): `twistAboutX` (the twist of a rotation given as its matrix rows, in (-pi, pi]) and `rotationAboutX`. Shared by the Ribbon's ends (`RibbonMath::extractTwist`) and the Swing constraint (`rigConstraint`'s `computeDelta`). |
| `Hash64.h/.cpp` | `Fnv1a64`, the one 64-bit hash every stored content hash uses (topology, skeleton), and `Hash64::format` / `parse`, its 16-hex-digit text (D35, D54). |
| `SkeletonFile.h/.cpp` | Skeleton file format (version 1): `SkeletonJoint`, `Skeleton`, `sortSkeletonJoints`, `skeletonHash` (markup, name, parent, rotate order, local rest rounded to 1e-4), `serializeSkeleton`, `deserializeSkeleton` (the stored hash is recomputed, never trusted), `skeletonUpdateTable` (D33), `skeletonParentsFirst` and `findSkeletonJoint` (D54). The file is a skeleton's only stored form: there is no skeleton `.ma`. | `describeSkeletonDifferences` (the joints that differ between two skeletons, for the look swap's error, D54).
| `SkinWeightFile.h/.cpp` | Weight file format (version 2, with `skeletonHash`): `SkinWeights`, `skinWeightUpdateTable` (D33), `topologyHash` (`Fnv1a64`), `sortSkinInfluences`, `findUnnormalizedVertices`, `serializeSkinWeights` / `deserializeSkinWeights` (D35). |
| `SkinWeightTable.h/.cpp` | Operations on a whole weight table, the home for the paintable skin tools to come (normalize, mirror, smooth). Now: `pruneToMaxInfluences`, on a table (rows are vertices, columns influences), the layout `getWeights` and `setWeights` use (D35). |
| `PoseFile.h/.cpp` | Pose file format (version 3, with `meta`): `PoseMap` (side, usage, channel values in UI units), `poseUpdateTable` (D33), `serializePose` / `deserializePose` (D34). |
| `LibraryMeta.h/.cpp` | The `meta` object of a pose and a ControlAnim file (D51): `LibraryMeta` (the rig's fields and the caller's), the field table, `libraryMetaToJson`, `parseLibraryMeta`, `applyCallerMeta` (the `meta` flag and `setRigDataFileMeta`), `renameVersion2MetaKeys` (the version 3 step both formats share, D54), `utcTimestampNow`. |
| `LibraryFile.h/.cpp` | What a library file holds without loading it (D51): `summarizeDataFile` (kind, meta, range, controls), `dataFileInfoToJson` and `dataFileErrorToJson` for `getRigDataFileInfo`, `editDataFileMeta`. |
| `JointClipFile.h/.cpp` | JointClip file types (`JointClip`, `JointPose`, `JointTransform`): the JSON file Python hands the plugin (D41): `deserializeJointClip` reads and validates it, and Python writes it. |
| `RigKeys.h/.cpp` | A rig's keys as plain data, by control markup and channel: `RigKeys` (a `ChannelCurve` per channel: `Key`s with `Tangent`s, `isWeighted`, the infinities), `serializeRigKeys` and `deserializeRigKeys`, the payload of `getRigKeys` and `setRigKeys` (D34, D42), `rigKeysToJson` and `parseRigKeys` for files, `negateCurve` and `offsetKeys`. |
| `ControlAnimFile.h/.cpp` | ControlAnim file format (version 3, with `meta`): `ControlAnim` (frame rate, range, `LibraryMeta`, `RigKeys`), `controlAnimUpdateTable` (D33), `serializeControlAnim` / `deserializeControlAnim` (D42). |
| `RigControlFilter.h/.cpp` | `RigControlFilter` for `getRigControls`: moduleType, side and usage lists. |

| `shared/ControlShapeScene.h/.cpp` | `getControlShape` / `setControlShape`, the rig-wide versions behind the shape file commands, and `mirrorRigControlShapes`. |
| `shared/ControlSpaceScene.h/.cpp` | A control's space of either kind (D52 phase 7): `getControlSpace` (a constraint's through `RigConstraintNode`, else a module-owned space found by the `space` enum's connection into a module whose descriptor has a `spaceDelta`; labels from the enum) and `setControlSpace` (the constraint's `matchSwitchSpace`, or the module's `spaceDelta` for the old and new space and `RigPoseScene::matchControlToNewDelta`). Behind `getRigControlSpace` and `setRigControlSpace`. |
| `shared/SkeletonScene.h/.cpp` | `SkeletonScene::readSkeleton`: marked joints into a `Skeleton` (parent is the nearest ancestor among them, rest local to it), checked through `JointMarkupScene::collectMarkedJoints` (D54). `createSkeleton` is its inverse: joints from a `Skeleton`, parents first, the rest in `translate`, `jointOrient`, `scale` and `shear` with `rotate` at zero and `segmentScaleCompensate` off, marked, failing when a name is taken. |
| `shared/SkinWeightScene.h/.cpp` | `SkinWeightScene` (mesh lookup, `meshId`, reading a skinCluster into `SkinWeights`, with the influences' rig `skeletonHash`) and `SkinWeightLoad` (undoable load: checks, influence edits, bind at rest, weights) and `SkinWeightPrune` (undoable prune). |
| `shared/LookScene.h/.cpp` | `LookSwap` (D54): the undoable look swap. Matches meshes to weight files by `meshId`, runs a `SkinWeightLoad` per mesh (which checks the file's `skeletonHash` against the rig), deletes the previous look's members and their history, names each new mesh after its file's `meshName`, and creates or updates the `lookRoot`. `LookScene::checkSkeleton` compares a look's `skeleton.json` with the rig's stamp. |
| `shared/Colors.h` | `Colors`, the Maya `MColor` constants, split out of `core/Constants.h`. |
| `shared/Side` | Enum/string helpers for sides. |
